## 1. 已经完成

正式扩展与内部验证工具都使用 `src/modules/pdf-core/` 中的唯一 D 实现。旧、A、B、C 的运行分支、选择器和差异对比已删除。文字提取、补框、归属、悬挂断段、阅读序、跨栏和跨页配对只维护一份。

文档按页码推进，已确定的内容先翻，末尾接续组等待后面的页；后文不会越过等待组。每段原文只归一个最终单元。翻译请求仍可并行返回，按成员的页码、块和段落标识写回。

MeowTabby 继续使用原有界面、文字段落包络、分簇规则、字符容量分配、字号求解和导出。新增页面不会把跨栏或跨页的几个矩形合成一个大盒。等待中的标题也保留原文可见。

原有 180°、270° 坐标错误已按 PDF.js 实际视口修正。筛选重放复用在途请求，刷新设置隔离旧响应，导出等待当前版本的译文并保护正在生成快照的画布。

验证器位于 `tools/pdf-verify/`，切片、评分、编号、原框/补框和段落框等功能保留。505 个原 JSON 文件已原样迁入。模型放在 `model-store/`，默认正式构建不带模型，验证构建读取该本地模型。内置模型直接读取实际打包字节，不复用旧远程缓存，也不会在加载失败时换用另一个模型。

## 3. 怎样使用

在 MeowTabby 根目录运行：

```sh
pnpm dev:pdf-verify
```

构建后，把 `tools/pdf-verify/.output/chrome-mv3` 加载为开发扩展。它与正式 MeowTabby 的 `.output/chrome-mv3` 是两个独立产物。

```sh
pnpm build:pdf-verify
pnpm check:pdf-packaging
```

如果本机 pnpm 自动获取工具链时无法继续，可以直接调用已经安装的程序：

```sh
node node_modules/wxt/bin/wxt.mjs build tools/pdf-verify
node scripts/check-pdf-packaging.mjs
```

详细操作见 [内部验证工具说明](../../tools/pdf-verify/README.md)。以后修改共用核心，再分别启动扩展和验证器即可，无须复制同步算法。已有切片目录需要在新的验证扩展里重新选择授权一次。
